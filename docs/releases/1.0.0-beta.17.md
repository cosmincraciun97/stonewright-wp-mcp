# Stonewright 1.0.0-beta.17

Released: 2026-10-18

Release channel: `supported`

## Summary

This supported public beta tightens who can run what through Stonewright and
signs its releases. A tool that runs or writes code needs the Full tool surface,
which an administrator chooses in wp-admin, on every route that can run it.
Making the mode less strict or switching an ability back on needs a person in
wp-admin, and connecting to the MCP servers needs `edit_posts`. From this
version on, the plugin installs an update only when the release's checksum
manifest carries a valid signature by the maintainer's release key. Plugin and
companion stay aligned on `1.0.0-beta.17`; Stonewright Visual stays `0.4.0`.

## Security

- Check the tool surface on every way an ability can be run. An ability that
  runs or writes code is refused unless an administrator chose the Full tool
  surface in wp-admin, whether it is called as an MCP tool, through
  `execute-ability`, the REST runner or WordPress's own Abilities API route, and
  a confirmation token no longer lifts that refusal.
  `security-issue-confirmation-token` issues no token for such an ability.
- Validate the input of `POST /stonewright/v1/abilities/run` against the
  ability's schema, as `execute-ability` does.
- Make the Direct task-start and learning-record routes respect the master
  toggle and the list of disabled abilities.
- Read the site mode through one accessor. A missing mode follows the
  environment, as it does on activation, and a damaged or unknown value counts
  as production-safe, so neither can loosen a gate.
- Require an administrator in wp-admin to make the mode less strict, switch a
  disabled ability back on or change feature flags. Requests signed in with an
  Application Password or OAuth can still make the mode stricter and switch
  abilities off.
- Check custom instructions the way memory is checked before they are saved
  through REST, `system-instructions-set` or a knowledge import.
- Require `edit_posts` to use the MCP servers, on the Application Password
  route and the OAuth route alike. Sites can change it with the
  `stonewright_mcp_required_capability` filter.
- Return site memory, custom instructions, recurring errors and incident
  actions from `task-start` and `context-bootstrap` only to administrators.
- `search-query` and `oembed-resolve` need `edit_posts`; `stock-image-search`
  needs `upload_files` and encodes the search terms it sends to the provider.
- Sign releases. This version ships the release public keys, an active key and
  an offline backup key, and installs an update only when the release's
  `SHA256SUMS.txt.sig`, an Ed25519 signature of `SHA256SUMS.txt`, verifies
  against one of them. A missing or wrong signature stops the update before the
  package is downloaded.
- Record a GitHub build provenance attestation for the plugin ZIP and the
  companion package. It adds no release asset.

## Changed

- Describe the update package check accurately: the ZIP is compared with the
  SHA-256 in its release's `SHA256SUMS.txt`.
- Leave the PHPStan stub folder out of the plugin release ZIP.

## Removed

- The `/stonewright/v1/sandbox/files` REST routes. Sandbox files are managed on
  the Sandbox Library admin page and with the sandbox abilities on the Full
  surface.

## How to update

Open Dashboard → Updates, click Check again, and update Stonewright from
`1.0.0-beta.16.2`. Automatic updates can take up to about 24 hours to find and
install the release. Earlier versions carry no release key, so they install
this one with the checksum check only; every update after it also needs a
valid signature. The companion has no change besides its version; updating its
package reference to the published beta.17 asset is optional.

After the update:

- A user without `edit_posts`, such as a subscriber or a shop customer, can no
  longer connect an MCP client. A site can require another capability with the
  `stonewright_mcp_required_capability` filter.
- Tools that run or write code, such as `php-execute`, need the Full tool
  surface. An administrator chooses it in Stonewright → Setup → Settings.

Published assets are `stonewright-1.0.0-beta.17.zip`,
`stonewright-companion-1.0.0-beta.17.tgz`, `SHA256SUMS.txt` and
`SHA256SUMS.txt.sig`. To check them by hand, run this next to the downloaded
files:

```bash
sha256sum -c SHA256SUMS.txt
```

Then check the signature from a checkout of the `v1.0.0-beta.17` tag, with the
paths of the downloaded files:

```bash
node scripts/release-signature.mjs verify --manifest path/to/SHA256SUMS.txt --signature path/to/SHA256SUMS.txt.sig
```

## Compatibility and safety

- WordPress plugin and companion: `1.0.0-beta.17`.
- Plugin mode registers **397** abilities;
  Direct full exposes **105** tools.
- WordPress: 6.7 or newer.
- PHP: 8.1 or newer.
- Node.js: 20 or newer for the companion.
- Updates preserve existing memory, user skills, audit history, the change
  history, Direct state and connected OAuth clients.
