# Stonewright 1.0.0-beta.19

Released: 2026-11-06

Release channel: `supported`

## Summary

This supported public beta fixes three write paths. A theme-file write on a
slow host is no longer rolled back for a check the host could not pass anyway,
and when a rollback cannot be blamed on the write, the grant it ran under can
be used once more. Saving an ACF field group by key updates the group that
already holds the key instead of adding a second copy of the group and its
fields, and a save that would delete fields now needs
`allow_field_removal: true`. `stonewright/theme-file-patch` can change text
inside one line, with `mode: replace_string` or `placement: exact`. The
companion code does not change. Plugin and companion stay aligned on
`1.0.0-beta.19`; Stonewright Visual stays `0.4.0`.

## Added

- `stonewright/theme-file-patch`, and the `theme-file` provider of
  `stonewright-custom-code-provider`, take `mode: replace_string` with an
  `old_string` that occurs exactly once in the file. That text is replaced
  byte for byte, so a change inside one line no longer needs markers.
  - A missing, empty or repeated `old_string` is refused
    (`stonewright_theme_file_old_string_missing`, `_required`, or `_ambiguous`
    with `matches`). Overlapping occurrences count as repeats.
  - `old_string` is never written to the audit log.
- `placement: exact` makes the other patch modes write the content byte for
  byte. Nothing is added after the marker or before `end_marker`, trailing
  spaces are kept, and line endings stay as sent. As a result:
  - an edit inside one line works with `replace_between_markers`;
  - sending the current block back reports no change and needs no approval;
  - the approval page shows only the lines that change, instead of every
    following line shifted.

  `placement: block`, the default, keeps the bytes it produced before, so
  proposals and grants already issued stay valid.
- `stonewright-acf-field-group-get` returns the post IDs of the group and of
  its fields (`group.ID`, `fields[].ID`), whether ACF also keeps the group in a
  JSON file or in PHP code (`group.local`), and the other posts that hold the
  same key (`group.duplicate_post_ids`). `include_settings: true` returns the
  full group array and the full field arrays (`parent`, `sub_fields`, `layouts`
  and every setting), capped at 200 fields or 256 KiB; above the cap the answer
  is `truncated: true` with the compact fields and `field_keys`, and
  `field_key` returns one field in full.
- `stonewright-acf-field-group-save` answers with `post_id`, `created`,
  `fields_created`, `fields_removed`, `created_post_ids`, `duplicate_post_ids`
  and `local`, and the contract mirror it keeps stores the payload with the
  resolved post IDs.

## Changed

- Removing fields from an ACF field group needs `allow_field_removal: true` on
  `stonewright-acf-field-group-save`. ACF deletes a field the payload leaves
  out permanently, so such a save is refused with
  `stonewright_acf_fields_would_be_removed` (the field keys in the error) and
  nothing is written until the call allows it. An agent that saves a group
  with only the fields it changes must now send the whole group, or allow the
  removal. The input and output schemas of `stonewright-acf-field-group-save`
  and the input schema of `stonewright-acf-field-group-get` changed; names,
  permission, backup, token, validation and audit gates are unchanged.

## Fixed

- Keep a theme-file write on a slow host that the health check after the write
  could not judge. As a result:
  - That check asks a check that passed before the write once more when it
    gets no answer. The one retry was skipped whenever a check that never
    passed (a wp-admin screen that times out on every request) had used up the
    time budget. Only the checks that can be judged count against it now, so a
    probe and its retries take at most 45 seconds instead of 30.
  - A page that took longer than 5 seconds to answer before the write is a
    slow witness. Its silence after the write is not held against the write,
    the evidence says so (`witness: slow` with `baseline_ms`), it is not asked
    a second time, and Check again no longer requires it. A failing answer
    still fails at once. The threshold is the filter
    `stonewright_rescue_probe_witness_ms` (1 to 30 seconds).
  - A write that was kept reports `verification_reason`, and `warnings` for the
    checks that reached no verdict. A write that was rolled back reports
    `verification_reason`, `post_rollback_reason` and `attribution`
    (`attributed`, `unattributed` or `unknown`) in its error and its evidence.
- Give the custom-code grant back once when a theme-file or `theme.json` write
  was rolled back for a check that is still lost with the original file back
  (`attribution` `unattributed`). The answer sets `custom_code_grant_status`
  to `reusable_once`, and the same bytes can be applied once more with the same
  grant before it expires. Every other rollback spends the grant as before,
  and the repair hint no longer asks for a new grant when the same one still
  applies.
- The `theme-file-patch` schema described `replace_between_markers` as
  "inclusive", but both markers have always stayed in the file. The schema now
  says so and describes where block placement puts the content: a newline after
  `start_marker`, the content with one trailing newline, and another newline
  before `end_marker`.
- Save an ACF field group by key as an update of the posts that already hold
  it. `stonewright-acf-field-group-save` handed the payload to ACF's importer
  as it came. Without the post ID of the group, ACF inserted a second
  `acf-field-group` post with the same key and a second copy of every field,
  so the edit screen showed two metaboxes and a field name resolved to either
  field. The save now resolves the group and its fields by key, so IDs are
  optional. It refuses:
  - a payload ID that belongs to another group or field
    (`stonewright_acf_group_id_mismatch`, `stonewright_acf_field_id_mismatch`);
  - a key that two posts hold, until the call names one with `group.ID`
    (`stonewright_acf_group_key_ambiguous`);
  - a group registered in PHP (`stonewright_acf_group_registered_in_code`);
  - a group or a payload whose fields nest more than 11 levels deep
    (`stonewright_acf_group_too_deep`), where the save could not see which
    fields ACF would delete.

  A group that exists only in local JSON is created, and the answer says so
  (`local`).
- Record every post an ACF field group save inserts in the change ledger. The
  ledger compared ACF's answer before and after the import, which names one
  post per key, so a duplicate group and its fields had no created row and a
  rollback could not remove them. The save now listens to `wp_insert_post`
  during the import and records each group or field post it inserts.

## Companion

- No change other than the version.

## Known limitation

- Through a local companion, one call waits 30 seconds for the site by
  default. On a host slow enough to need the longer health check, a theme-file
  or `theme.json` write and its checks can take longer. The companion then
  reports a timeout while the site still finishes the write and keeps it or
  rolls it back. Read the outcome with `stonewright-change-history-list`
  before you send the write again. The companion's `STONEWRIGHT_MCP_TIMEOUT_MS`
  environment variable, in milliseconds, raises the wait.

## How to update

Open Dashboard → Updates, click Check again, and update Stonewright from
`1.0.0-beta.18.1`. Automatic updates can take up to about 24 hours to find and
install the release. The plugin installs this update only when the release's
`SHA256SUMS.txt.sig` verifies against one of its release keys.

The companion code is the same as in `1.0.0-beta.18.1`. A companion on
`1.0.0-beta.18.1` only aligns its version by moving to the beta.19 asset. A
companion older than that needs the update for the `MCP-Protocol-Version` fix
in [1.0.0-beta.18.1](1.0.0-beta.18.1.md). For an alias-based install, the
versioned repair command points the client at the new asset and keeps the
stored credential reference:

```bash
npx -y --package https://github.com/cosmincraciun97/stonewright-wp-mcp/releases/download/v1.0.0-beta.19/stonewright-companion-1.0.0-beta.19.tgz stonewright connect repair <alias> --client <client> --mode plugin-only
```

Fully restart the AI client, then run `connect verify` for the alias. See
[Updating Stonewright](../updates.md) for the other install types.

Published assets are `stonewright-1.0.0-beta.19.zip`,
`stonewright-companion-1.0.0-beta.19.tgz`, `SHA256SUMS.txt` and
`SHA256SUMS.txt.sig`. To check them by hand, run this next to the downloaded
files:

```bash
sha256sum -c SHA256SUMS.txt
```

Then check the signature from a checkout of the `v1.0.0-beta.19` tag, with the
paths of the downloaded files:

```bash
node scripts/release-signature.mjs verify --manifest path/to/SHA256SUMS.txt --signature path/to/SHA256SUMS.txt.sig
```

## Compatibility and safety

- WordPress plugin and companion: `1.0.0-beta.19`.
- Plugin mode registers **397** abilities;
  Direct full exposes **105** tools.
- WordPress: 6.7 or newer.
- PHP: 8.1 or newer.
- Node.js: 20 or newer for the companion.
- Theme-file proposals and grants issued before the update stay valid:
  `placement: block`, the default, writes the same bytes as before.
- Updates preserve existing memory, user skills, audit history, the change
  history, Direct state and connected OAuth clients.
