# Stonewright 1.0.0-alpha.88

## Added

- Design Studio in wp-admin: overview, structured editor, live specimen,
  provenance, quality evidence, and revision history. Saving, activation,
  restore, and Elementor synchronization use review drawers and the existing
  typed design abilities instead of a second write path.
- Eight REST routes under `stonewright/v1/design-studio`. They delegate to the
  existing design-direction and quality owners, preserving permission, task
  context, confirmation-token, backup, validation, audit, and effect-readback
  gates.
- Reviewed skill lifecycle in wp-admin: source registry, catalog, editor,
  two-step import bound to a SHA-256 content hash, normalized export with
  provenance, trash, undo, restore, and production-safe permanent deletion.
- `visual-direction`, a built-in skill pack for direction capture, reviewed
  Elementor kit synchronization, first-section checkpoints, and rendered
  evidence.
- Visual Workspace in wp-admin. It detects Elementor V4, Elementor V3, or
  Gutenberg without falling through an undrivable editor, then enforces the
  read, preview, confirm, apply, and verify sequence through the existing typed
  adapters.
- A packaging-required browser bundle for the Visual Workspace. Source
  checkouts may omit it, but CI and release packaging stage it into
  `plugin/assets/visual/workspace-browser.js` and fail if the plugin archive
  does not contain it.

## Fixed

- Design Studio editing preserves contract sections that the form does not
  expose, including components, provenance, waivers, and readiness.
- Write outcomes remain in the live region after a view re-renders.
- Revision history explicitly opts into stored versions, so real saved
  revisions are listed and can be restored.
- Visual Workspace no longer treats block libraries loaded on a plain admin
  screen as proof that Gutenberg is connected.

## Evidence semantics

- No page certifies that a design is correct. A Design Direction supplies
  intent; a quality report supplies measurements and states its own coverage.
  A change without evidence behind it is reported as unverified, not complete.

## Abilities and gates

- No MCP ability was added, removed, renamed, or changed. Design Studio REST
  routes delegate to existing abilities; Visual Workspace uses existing typed
  adapters.
- Skill lifecycle adds real permission checks to every REST route, audit records
  for every mutation, server-side import validation, and a confirmation token
  bound to the skill id for permanent deletion in production-safe mode.
- Existing Elementor backup, validation, confirmation-token, audit, surgical
  mutation, breakpoint-integrity, and readback gates remain unchanged.
- The plugin exposes **329** abilities; Direct mode exposes **99** tools.

## Package versions

- WordPress plugin and companion: `1.0.0-alpha.88`.
- `@stonewright/visual`: `0.4.0`, reflecting the new public workspace browser
  entry and workspace UI surface.

## Verification

- Plugin unit, integration, and contract suites; static analysis; coding
  standards; security, dependency, provenance, token, package, contract, and
  documentation gates; companion and Visual typechecks, tests, and builds; and
  the full browser matrix pass before tagging.
- The browser matrix covers Design Studio save, activate, history, and restore
  against real routes, Skills Studio lifecycle states, and the 160-test Visual
  Workspace matrix across ten viewport and colour-scheme projects.

## Upgrade

Update both the WordPress plugin and local companion to `1.0.0-alpha.88`, then
restart the AI client so it loads the matching companion.
