# Stonewright 1.0.0-alpha.92

## Native rules

- Add one validated native-rule registry shared by Plugin and Direct mode.
  Every record declares severity, scope, rationale, and whether a concrete
  runtime guard or an instruction enforces it.
- Add `stonewright/rules-get` and `stonewright-rules-get`, with digest caching,
  severity/scope filters, and `knownDigest` short-circuit responses.
- Source task-start batching guidance from the registry. Compact task start
  carries the digest and resolver instead of repeating every rule body.
- Fail closed when either packaged registry is malformed, contradictory, or
  contains duplicate ids.

## Safer writes and audit

- Make escaped-layout decoding explicit through `decode_escaped_layout`. It is
  off by default and only decodes conservative PHP, CSS, or JavaScript layout
  escapes before confirmation, validation, candidate hashes, or writes.
- Bind confirmation tokens to the canonical payload bytes used by
  `php-execute`, `sandbox-write`, `theme-custom-css`, and `theme-file-patch`.
- Classify OAuth 4xx protocol outcomes as auth warnings while preserving 5xx
  server failures as incidents. Allowlisted diagnostics redact echoed request,
  response, bearer, Basic, and Authorization credentials.
- Add cursor-based `stonewright/memory-generalize`. It previews by default,
  requires the normal context/permission/token gates for apply, and reports
  partial database failures explicitly.
- Correct Elementor responsive control and standalone visibility detection.

## Cheaper, truthful reads

- Add optional `stonewright_fields` response projection to every ability. It
  preserves the `ok` envelope, source list order, and integer-keyed maps.
- Add `knownHash` to
  `stonewright/elementor-v3-get-page-structure`. Unchanged documents return a
  compact receipt without rebuilding the outline/tree.
- Canonicalize associative tree keys for hashing while preserving semantic
  Elementor element-list order.

## Admin and documentation

- Ship one supported light admin theme. The obsolete toggle, stored dark
  preference, duplicate token palette, and dark Playwright projects are gone.
- Keep one tooltip owner and preserve primary Visual Workspace button contrast
  on hover.
- Refresh all maintained READMEs, changelogs, installation prompts,
  architecture diagrams, capability references, generated contracts, and the
  implementation handoff.
- Upgrade WordPressCS and E2E tooling to patched dependency versions.

## Abilities and gates

- Plugin mode exposes **332** abilities; Direct mode exposes **100** tools.
- Added abilities: `stonewright/rules-get` and
  `stonewright/memory-generalize`.
- Existing permission, backup, DesignSpec validation, production confirmation,
  Elementor integrity, audit, and readback gates remain in force.

- 6,208 plugin tests / 32,180 assertions pass, together with PHPStan, PHPCS,
  security, dependency, provenance, public-contract, token-budget, package,
  and documentation gates.
- Companion lint/typecheck, 345 tests, contracts, token budgets, dependency
  audit, and build pass.
- Visual typecheck, 80 tests, dependency audit, and build pass.
- GitHub CI passes on PHP 8.1–8.5. The wp-env Playwright job passes 305 tests
  across five supported light-theme desktop, tablet, and mobile projects.
- Release archives and `SHA256SUMS.txt` are verified again by the tag workflow
  before publication.

## Upgrade

Update both the WordPress plugin and companion to `1.0.0-alpha.92`, then restart
or reload the MCP client. Existing Elementor documents, design directions,
memory rows, and admin settings are not rewritten during the upgrade.
