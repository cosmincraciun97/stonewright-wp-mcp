# Stonewright 1.0.0-beta.15

Released: 2026-10-12

Release channel: `supported`

## Summary

This supported public beta adds the change history with the **Changes** page,
checks permissions per user, template and object, limits code execution to
the `full` profile and to administrators who can edit plugins, makes Direct mode
refuse writes on a site where the plugin is active, and adds a route to
Elementor's own MCP module. Plugin and companion stay aligned on
`1.0.0-beta.15`; Stonewright Visual stays `0.4.0`.

## Highlights

- **Change history and the Changes page.** **Stonewright > Activity > Changes**
  lists what abilities changed, with a diff, **Undo** and **Redo**. Agents and
  WP-CLI read it with `stonewright-change-history-list`,
  `stonewright-change-diff-get` and `stonewright-change-rollback`.
- **Code execution is limited.** `php-execute` is on the `full` profile only,
  and Full is chosen in wp-admin, never by an agent. Running code needs
  `edit_plugins`.
- **Permissions are checked per object** in the user, Theme Builder, settings,
  change log and read abilities.
- **Direct mode refuses writes on a site where the plugin is active**, and
  takes the plugin's argument names, backups, readback and confirmations that
  are bound to the call.
- **Elementor's own MCP module** is reported and reachable through
  `stonewright-elementor-native-execute`, and direct calls to it are recorded.
- **Stonewright works beside plugins that bundle the MCP adapter**, such as
  Rank Math.
- **Check again finds a new release at once.**

## Upgrade notes

### Behaviour changes you will notice

**Code and commands**

- **`php-execute` is on the `full` profile only.** The other profiles and
  `discover-execute` no longer list or run it, and a client on one of them no
  longer sees it. The `tool-profile` `extras` setting refuses `php-execute`,
  the sandbox writers, the WP-CLI runners, `custom-code-provider` and the custom
  widget definers.
- **Full is chosen in wp-admin.** The `full` profile can be chosen only by an
  administrator under **Stonewright > Setup > Settings > MCP tool surface**.
  `stonewright-tool-profile` does not activate it, with or without a
  confirmation token, and the REST setting that puts the Full surface in effect
  accepts only a wp-admin request. Setting `STONEWRIGHT_MCP_TOOL_PROFILE=full`
  on the companion is unchanged.
- **Running code needs `edit_plugins`.** `php-execute`, `wp-cli-run`,
  `wp-cli-batch-run` and `wp-cli-job-start` need `edit_plugins` and
  `manage_options`, and a super admin on multisite. While `DISALLOW_FILE_MODS`
  is set, `php-execute` and the WP-CLI abilities refuse file-writing work.
- **`wp-cli-batch-run` is read-only.** It runs read-oriented commands only and
  refuses a batch with one command off that list before any command runs. Use
  `wp-cli-job-start` for a batch of writes.
- **WP-CLI dangerous groups are refused.** `config`, `scaffold`, plugin and
  theme `install`, `update`, `delete` and `activate`, `db` except its read-only
  subcommands, `user` and role changes, `core download`, `update` and `install`,
  `cron event run`, `cli update`, `search-replace` without `--dry-run`, writes
  to sensitive options, and the `--config`, `--ssh` and `--http` flags are
  refused in the companion runners and the WP-CLI abilities, in addition to
  `eval`, `eval-file`, `shell`, `package`, `--exec`, `--require` and `--prompt`.
- **Snippet rollback needs approval.** Rolling back a WPCode or Code Snippets
  snippet through `custom-code-provider` needs the one-time grant an administrator
  issues, like an apply.

**Permissions**

- **User checks.** `user-update` and `user-delete` check the specific user, a
  role change needs the permission to promote users and an editable role, the
  last administrator cannot be demoted or deleted, and `default_role` refuses
  roles that can manage the site.
- **Theme Builder and template checks.** The `theme-builder-*` abilities need
  `edit_theme_options` and `edit_post` on the template. `theme-builder-delete-template`
  moves the template to the trash and refuses `force`.
- **Other checks.** `comment-create` needs `edit_post` on the target post,
  `comment-get`, `-update` and `-delete` check the comment, `media-get` and
  `media-list` check each attachment, `memory-list`, `memory-get` and
  `system-instructions-get` need `manage_options`, and `blueprint-apply` with
  `mode: publish` needs the publish capability.
- **Elementor writes by a user without `unfiltered_html`**, or on a site that sets
  `DISALLOW_UNFILTERED_HTML`, are filtered the way Elementor's editor filters
  them and succeed; the receipt says `content_filtered: true`.

**Sites and modes**

- **Multisite sub-sites get a mode from the environment type.** A sub-site with
  no stored mode runs as `production-safe` on a `production` environment and as
  `staging` on `staging` on its first request after the update, and gets the
  `essential` tool surface where the plugin never ran. Before, it ran as
  `development`. A stored value is
  never replaced. To keep the old behaviour on a site, save `development` in
  **Setup > Settings**.
- **Direct mode refuses writes on a site where the plugin is active.** Direct
  reads the REST index and refuses a write with
  `stonewright_direct_write_blocked_plugin_present`; reads work. When the index
  cannot be read, the write is refused with `stonewright_direct_plugin_check_failed`.
  A session in `auto` mode never falls back to Direct while the plugin is live.
- **Direct mode needs a bound `confirmation_id` on remote sites.** A plain
  `confirm: true` no longer confirms a destructive Direct call on a site that is
  not local. The refused call returns a `confirmation_id` bound to the tool, the
  site and the exact arguments, valid for 10 minutes and one use.
- **Direct memory is keyed by site URL.** Two aliases for one site share its
  memory. A file keyed by alias is copied once, never moved or deleted.
- **Direct mode refuses custom code** in every write that sends text, holds a
  local WP-CLI write to a write gate, limits `settings-update` to an allowlist,
  and never retries a write.

**Knowledge and memory**

- **Skill and expertise promotion needs an administrator's approval.** A
  promotion stages a request and returns an approval link; the **Pending
  approvals** card on the Skills screen approves or rejects it. An approval works
  once, for that exact item, and expires after an hour.
- **Memory text that tries to override rules is held for review.** A saved
  lesson or memory entry that tells an agent to override the plugin's rules, to
  disable confirmation tokens or to send credentials elsewhere is stored as
  `needs_review` and is not offered until an administrator approves it on the
  **Memory** page.

**New pages and integrations**

- **Rescue history and the Changes page.** Each change made by an ability is
  recorded in the `stonewright_changes` table with the content before and after,
  and is listed under **Stonewright > Activity > Changes** (marked EXP). Defaults
  keep 90 days, 500 changes and 100 MB. Undoing code needs an administrator on
  the page.
- **Elementor native MCP.** When Elementor's MCP module is on (enable Elementor >
  Elementor MCP; the option is `elementor_mcp_enabled`, off by default),
  Stonewright reports it and `stonewright-elementor-native-execute` runs the
  certified abilities inside its safeguards. Elementor's own tools called
  directly are recorded in the change history and the Audit Log.
- **Plugins that bundle the MCP adapter.** Stonewright serves its MCP routes when
  another plugin, such as Rank Math SEO, loads its own copy of the adapter
  first. When a copy cannot be used, an administrator notice and the
  **Troubleshoot** page name the plugin that owns it.
- **Check again.** **Dashboard > Updates > Check again** reads the release list
  from GitHub, for an administrator who can update plugins, so a release
  published in the last 12 hours appears at once.

### Other changes that can affect existing calls

- `content-create-post`, `content-bulk-create` and `content-bulk-upsert-posts`
  refuse attachments, revisions, menu items and other internal post types;
  `content-update-post` refuses a revision id.
- Comment status is one vocabulary (`approve`, `hold`, `spam`, `trash`), and
  `comment-delete` moves a comment to the trash unless `force` is set.
- `media-set-alt` and every `blocks-batch-mutate` write need a confirmation token
  in production-safe mode. `media-upload`, `media-upload-batch` and
  `stock-image-import` refuse a file over 25 MB.
- `stonewright-elementor-v4-migrate` returns its error codes with one prefix
  and needs a confirmation token in production-safe mode.
- The `elementor-v3-kit-batch-mutate` `global` bucket is gone; the kit keys
  are `system_colors`, `custom_colors`, `system_typography` and `custom_typography`.
- Widget files that were defined but never registered are no longer loaded;
  register them with `stonewright-elementor-widget-register`.
- An error that waits for a person (a promotion, a custom-code grant, a snippet
  rollback, an undo of code, a request for the `full` profile) now carries its
  approval link in the text an MCP client receives.

### Rescue history and retention

- The table `stonewright_changes` is created on the first request after the
  update. Its stored copies are in `uploads/stonewright-state/blobs/`. Passwords,
  keys, salts, OAuth tokens and `wp-config.php` are never stored.
- A plugin delete, a password change and a `php-execute` run are recorded and
  marked not restorable.
- Removing all plugin data (`STONEWRIGHT_REMOVE_ALL_DATA`) also drops the table and
  the stored copies.

### How to update

Open Dashboard → Updates, click Check again, and update Stonewright from
`1.0.0-beta.14`. On `1.0.0-beta.14` the Updates screen reads a release list it
keeps for up to 12 hours, so the update can take that long to appear there;
from `1.0.0-beta.15` on, Check again reads the release list at once. Automatic
updates can take up to about 24 hours to find and install the release. Update the companion package reference to the published
beta.15 asset, fully restart the MCP client, then run:

```bash
npx -y --package <published-companion-package> stonewright connect verify <alias> --client <client>
```

In Direct mode the companion copies its built-in skills to the local skills
folder only when they are missing, so an existing install keeps its earlier
copies. To get the beta.15 versions, remove the built-in skill folders from the
companion's local skills folder before you restart the client; your own skills
are not affected.

Published assets are `stonewright-1.0.0-beta.15.zip`,
`stonewright-companion-1.0.0-beta.15.tgz`, and `SHA256SUMS.txt`.

## Change history and Rescue

- **Changes** lists changes newest first with filters for family, resource,
  ability, user, date range and result. **View diff** shows the content before
  against after, with secrets shown as `[redacted]`.
- **Undo** and **Redo** show the diff of what they would change, warn about a
  newer change to the same item, need the same nonce, administrator check and
  production-safe token as Rescue, and probe the site afterwards. If the site
  stops loading, the earlier state is put back (`stonewright_change_rollback_reverted`).
- Covered: posts and their kinds, options, theme switches, menus, widgets, theme
  files, snippets, the Customizer CSS, sandbox files, users, comments, media,
  WooCommerce items, site memory, skills and design directions.
- `wp stonewright changes list`, `diff <change>` and `rollback <change>` do the
  same from the command line; the command line cannot approve code.
- Elementor snapshots are taken from the real storage: a default-style write, a
  class and a variable change can be undone, and an undo or restore no longer
  makes the next Elementor save of the page fail with
  `stonewright_elementor_stale_editor`.

## Permissions and code execution

- Per-target checks in the user, Theme Builder, settings, change log, plugin and
  read abilities; refusals come before a confirmation token is used.
- `tool-profile` `extras` and `execute-ability` cannot enable code-running
  abilities; `execute-ability` validates arguments against the input schema.
- The HTML widget policy and the custom code gate apply to whole trees in
  `elementor-build-tree` and `replace_tree`; `elementor-build-tree` binds its
  confirmation token to the whole call.
- `theme-builder-apply-template` requests `verify_url` only on the site's own
  host; the audit log is not a scope of `security-runtime-data-purge`.
- Every admin page and handler that refuses a user answers HTTP 403.

## Direct mode

- Backups: `stonewright-direct-backup-list` and `stonewright-direct-backup-restore`
  list and restore the copies Direct saves, hash-checked and undoable.
- Every typed write is read back; a difference is `ok:false`. The public page can
  be checked after a page, post or template write.
- Elementor: `elementor-data-get` returns a tree `hash`, and `elementor-data-update`
  takes `expected_hash` and refuses duplicate ids, widgets at the root, CSS in a
  colour setting and oversized trees.
- Plugin argument names are accepted in the 37 Direct tools that share a name
  with a Plugin tool, and the plugin's output keys are added beside Direct's.
- `stonewright-blocks-batch-mutate` edits blocks by path, `memory-delete` removes
  a lesson, and memory is ranked by confidence and time since last confirmed.
- Direct tools act on the session's site, and a `site` argument that names another
  alias is refused with `site_not_in_session`.
- The Direct tool count is **105**.

## Elementor V3 and V4

- Writers take the page or kit lease before they read, so two writers no longer
  overwrite each other; a busy page answers `stonewright_elementor_write_busy`.
- `elementor-v3-update-kit-colors` and `-typography` merge rows by `_id`.
- Moving a container sets `isInner` from the destination; a widget at the root is
  refused.
- V4 class and variable snapshots cover what the write changes; widget files are
  written through the sandbox writer; `elementor-v4-migrate` takes the page lock.
- `elementor-v3-batch-mutate` has an `add_inner_section` action.
- Writes that clear CSS by themselves purge the cached page of the post for the
  page cache plugins Stonewright finds (`cache_purge`); other caches are still
  purged by hand.

## Gutenberg and FSE

- Block, pattern, template, navigation and global-style writers stop with
  `stonewright_backup_failed` when their snapshot cannot be stored.
- `blueprint-apply` keeps the status of an existing page and removes a page it
  created when the write fails; `theme-activate`, `menu-assign-location` and
  `fse-create-template-part` validate their target.
- `theme-json-handoff` refuses without an active child theme.

## Admin UI

- One control size for buttons and fields, aligned filter rows, and a layout
  check of every Stonewright page.

## Companion

- The Direct changes above, the WP-CLI refusals, and a media upload that is
  limited to allowed paths, types and 25 MiB and connects to the address it checked.
- `stonewright-tool-profile` does not switch to `full`.

## Security fixes

- Object-level permission checks, code-execution limits, the approval for
  promotion and snippet rollback, and the memory review screen listed above.
- `comment-create` goes through core's comment pipeline; `content-bulk-upsert-posts`
  checks every item before writing any.
- `stock-image-import` and `media-upload` limit the type and size they accept.

## Known limits

- Direct mode does not yet take a snapshot before every write. Plugin, theme,
  settings, menu, media, ACF, taxonomy, comment, user and widget writes save
  no pre-image.
- Direct mode has no per-post lock around an Elementor write, and
  `expected_hash` is optional.
- Direct `rest-request` and local WP-CLI writes are not read back.
- Direct restore writes the saved meta back and deletes no key added later, so
  `matches_backup` can be false after a correct restore.
- Direct does not take `move` or `insert_section` in `blocks-batch-mutate`.
- The native route covers `build-composition`, `get-page-structure` and
  `manage-default-styles`; `manage-classes` and `manage-global-variable` are
  certified but go through the Stonewright V4 writers. The contracts cover
  Elementor 4.3.x (verified 4.3.0 to 4.3.4); another version is reported with
  `elementor_version_out_of_range`.
- `provider-discovery` lists `descriptor_unavailable` groups for types it can list
  but not write natively; they affect nothing else.
- `elementor-post-write-verify` reports Elementor V4 widgets as absent.
- Section copies do not rename the anchor of a Menu Anchor widget.
- The V4 renderer does not render `spacer`, `list`, `video`, `embed` or `slider`
  blocks.
- Elementor V4 section copies stay blocked in production-safe mode.
- `drop_settings` applies to Elementor V3 sections only.
- A full uninstall does not remove `uploads/stonewright-private`; delete it by
  hand if needed.
- The companion's first refresh request has no timeout of its own; only its retry
  is bounded.
- Going back to 1.0.0-beta.14 is not supported. The change history table and its
  stored copies stay in the database and the uploads folder and are not used.
  The Rescue helper `wp-content/mu-plugins/stonewright-rescue.php` also stays.

## Compatibility and safety

- WordPress plugin and companion: `1.0.0-beta.15`.
- Plugin mode registers **397** abilities;
  Direct full exposes **105** tools.
- WordPress: 6.7 or newer.
- PHP: 8.1 or newer.
- Node.js: 20 or newer for the companion.
- Updates preserve existing memory, user skills, audit history, Direct state
  and connected OAuth clients.
