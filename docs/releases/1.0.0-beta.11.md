# Stonewright 1.0.0-beta.11

Released: 2026-08-22

Release channel: `supported`

## Summary

This release closes the Gutenberg live-editor write path, makes connection
setup diagnosable in place, and keeps compact agent sessions honest about
context, design direction, and tool-surface size. Plugin and companion stay
aligned on `1.0.0-beta.11`.

Operators get a Troubleshoot page, a visible Block Editor Queue with
explicit per-id cancellation, local WP-CLI command recipes with one-use
approval for writes, and an admin shell that no longer crowds the header
with mode and version. Writers
that were missing production-safe confirmation now require it. Skills stay
presence-gated, industry landing-page playbooks leave the catalog, and
recurring failures become reviewable draft lessons after ten repeats.

## Added

- Add in-place connection diagnostics with bot/WAF probes, OAuth registration
  checks, clipboard fallback, and a copyable support report.
- Add a browser-assisted Gutenberg finalizer that serializes queued block specs
  in the live editor iframe, persists path-aware hashed HTML, and shows Block
  Editor Queue heartbeat status. Partial schemas stay live-editor validated.
- Add a discover-execute MCP profile, bounded Gutenberg/FSE read summaries,
  Elementor list-widgets summary mode, and optional full Design Direction
  document loading from `stonewright/design-direction-brief`.
- Add presence-gated builder operating manuals plus ACF, SEO, and forms skills,
  typed query-loop / navigation / pattern lifecycle abilities, theme chrome
  get/update, and a read-only Elementor performance audit.
- Add reviewable draft lessons when the same recurring error reaches ten repeats.
- Add motion capability discovery, strict semantic DesignSpec validation,
  static-first bundled presets, signed renderer plans, guarded Gutenberg/FSE
  and Elementor V3 apply, and motion/UI evidence in design-quality reports.

- Add verified design-direction deactivation through the existing
  `stonewright/design-direction-activate` ability (`id: 0`) plus an admin
  Active toggle that autosubmits and reports failures honestly.
- Add `stonewright/blocks-finalizer-cancel`: explicit per-id cancellation of
  queued, serialized, or failed finalizer records with dry-run, per-post
  permission checks, production-safe confirmation tokens, atomic deletion,
  and verified readback.
- Add local WP-CLI command recipes v1 in the companion: parameterized recipes
  per site, one-use plan approval for write recipes, stop-on-error execution,
  bounded redacted output, and a final read-only verification step enforced at
  save time. Three MCP tools (`stonewright-command-list/get/run`) ship only on
  wp-cli, site-admin, full, and discover-execute profiles.

## Changed

- Keep compact `stonewright-task-start` under the anti-slop byte budget with
  truncated Context, `design_direction_ref`, and the visual quality floor.
- Clear the admin header of mode and version, mark Troubleshoot, Context,
  Design, and Block Editor Queue as Experimental, and move Memory, Skills, and
  Context under Workflows.
- Split paste-to-agent `--profile` from `--wp-surface`, persist the MCP surface
  from Apply now, and report when a session has widened beyond compact.
- Presence-gate skill bodies as well as the catalog. Load playbook bodies only
  through `stonewright/skills-get`.
- Expose the generated **387**-ability Plugin and **101**-tool Direct contracts
  throughout maintained documentation.

## Security

- Motion plans are site-signed and fail closed on operation, asset, capability,
  direction, or renderer drift. Elementor V3 motion writes require complete
  live schema/runtime/source evidence and a current tree hash.
- Isolate the Gutenberg finalizer queue per owner, session, and target post.
  Records carry owner/session/post, tokens are HMAC-bound to all four values,
  results are scoped per actor, replay after terminal states is refused,
  legacy unbound records fail closed, and queue mutations run under a bounded
  mutex. Hard limits bound batch size, open records per user, total records,
  spec bytes, tree depth and nodes, serialized HTML bytes, and total state
  size; terminal records prune on retention schedules.

## Fixed

- Keep every Stonewright admin navigation link visible and contained at 320px
  and 390px by allowing multi-link header groups to wrap inside the mobile
  shell.
- Load motion assets only on marked documents, distinguish load and viewport
  triggers, execute stagger/duration/delay configuration, ensure played targets
  outrank the initial hidden state, and fail open when the frontend runtime
  cannot initialize.
- Derive V4 interaction triggers, breakpoint support, and write readiness from
  the loaded Elementor runtime. Native V4 motion apply stays unsupported when
  the official typed mutation primitives are incomplete.
- Fix the security-audit assert-call detector to use token-based PHP parsing:
  grant-gate method assertions no longer produce false positives while
  functional `assert()` calls stay blocked.

- Separate Codex Desktop from Codex CLI in Connect and dedupe generated MCP
  server names.
- Hide Elementor V4 tools when the atomic toggle is off.
- Surface audit-row error code, message, target, and repair; occurrence links
  filter correctly.
- Harden memory save failures, checkbox uncheck, matching window, and
  `body_tool` routing.
- Normalize sparse container settings on the standalone add-container path.
- Restore editor iframe state after finalizer serialize and honor block path,
  position, and update semantics on persist.
- Store backup snapshots through a slash-safe post-meta boundary so escaped
  Elementor JSON round-trips byte-faithfully.

## Removed

- Remove packaged industry landing-page playbooks from the skills catalog.
  Already-seeded playbook rows are retired on seed and on plugin upgrade.

## Upgrade

After maintainer approval and publication, update the plugin from its native
WordPress updater or install the published release ZIP. Update the companion
package reference to the published beta.11 asset, fully restart the MCP client,
then run:

```bash
npx -y --package <published-companion-package> stonewright connect verify <alias> --client <client>
```

Success requires the requested alias, expected companion version,
`stonewright-task-start`, status availability, and an empty
`refresh_required_tool_names` list.

## Compatibility and safety

- WordPress plugin and companion: `1.0.0-beta.11`.
- Plugin mode registers **387** abilities; Direct full exposes **101** tools.
- WordPress: 6.7 or newer.
- PHP: 8.1 or newer.
- Node.js: 20 or newer for the companion.
- Production-safe confirmation now covers remaining content, Elementor,
  Gutenberg, site, and admin-domain writers. php-execute stays read-only at
  runtime and off default compact surfaces. Elementor backup, DesignSpec
  validation, and custom-code approval boundaries remain unchanged.
- Fresh installs start without user memory, user-created skills, incidents, or
  audit history. Updates preserve existing private state.

The release workflow generates and verifies the plugin ZIP, companion package,
Visual package, and `SHA256SUMS.txt` before publishing installation assets.
