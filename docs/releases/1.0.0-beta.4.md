# Stonewright 1.0.0-beta.4

This release turns recurring runtime failures into explicit, testable product
contracts. It separates blocked policy outcomes from repairable incidents,
closes OAuth refresh rotation, makes Elementor and Gutenberg mutations
transactional, and adds evidence-first design planning without customer data.

## Audit, incidents, and cleanup

- Audit events use a versioned taxonomy with one root error, bounded redacted
  evidence, stable resource fingerprints, retry metadata, and transaction or
  change-set correlation.
- Incidents move through `observing`, `open`, `resolved`, and `suppressed`.
  Permission and safety blocks no longer become false repair debt, and a
  correlated verified success is required for resolution.
- Legacy audit rows reconcile idempotently into the new event and incident
  model. The unresolved-memory view now reads the first-class lifecycle store.
- `stonewright/security-runtime-data-purge` previews counts and hashes without
  row bodies, requires exact reviewed hashes and production confirmation, and
  deletes only through reviewed numeric watermarks. Concurrent rows survive
  and force a visible failure. One redacted cleanup receipt remains.
- Redacted CSV exports neutralize spreadsheet-formula prefixes.

## OAuth reliability

- Companion token storage uses atomic replacement and restrictive file mode.
  Refreshes are single-flight, retries are bounded, `Retry-After` is honored,
  and terminal OAuth errors clear durable state.
- Every successful refresh must return a new refresh token. Omission or replay
  of the old token now requires reauthorization instead of reusing a rotated
  credential.
- Server-side rate limiting keys client identity with bounded network buckets,
  trusts forwarded addresses only behind configured proxies, emits bounded
  diagnostics, and covers both token and registration entry points.

## Transactional content writes

- Elementor V3 mutation uses one post lease, one snapshot, one persistence
  write, one readback, and one rollback decision. Receipts carry before,
  planned, after, and verification hashes plus bounded recovery guidance.
- Surgical patches preserve untouched unknown settings. Removing an unknown
  key requires an exact approved preservation hash; ordinary merges cannot
  acquire that permission.
- Repeater identities and responsive scope are validated. ID-only document
  repair cannot alter content, settings, order, type, or hierarchy.
- Legacy Elementor debt has separate report and explicit migration abilities.
  Mixed V3/V4 documents route to safe roots and are never silently converted.
- `stonewright/blocks-batch-mutate` gives Gutenberg one snapshot, write,
  readback, and rollback boundary for insert, update, move, and remove.

## Design evidence and diagnostics

- Section manifests provide deterministic bounds, provenance, assets,
  responsive intent, and native renderer requirements without inventing
  missing measurements.
- Carousel intent requires per-viewport geometry and verified arrow assets.
  Inline SVG is parsed through element and attribute allowlists.
- Native renderer selection requires a registered candidate and live schema
  hash. Visual comparison returns bounded geometry, typography, spacing,
  color, missing-measurement, and extra-element findings.
- Read-only diagnostics distinguish OAuth header delivery, object-level
  capability, and form-provider infrastructure without exposing credentials,
  recipients, or message bodies.

## Verification

Release gates cover the complete PHP, companion, and Visual test suites;
PHPStan and PHPCS; security and dependency audits; public API and generated
contract checks; token budgets; documentation freshness; public-repository
hygiene; staged plugin and npm package inspection; archive secret scanning;
and WordPress/WooCommerce activation from the extracted release package.

Release assets contain the versioned plugin ZIP, companion TGZ, Visual TGZ,
and `SHA256SUMS.txt`.

## Upgrade

For local stdio in Plugin mode, update both packages to `1.0.0-beta.4`, restart
the AI client, call `stonewright-task-start`, and verify
`companion_version`, `expected_companion_package`, and
`refresh_required_tool_names`. Remote Streamable HTTP updates only the plugin;
pluginless Direct mode updates only the companion.

Updates preserve existing memory, user skills, audit history, settings, and
Direct state. Runtime history is erased only by the explicit reviewed purge
flow described above.
