# Stonewright 1.0.0-beta.19.1

Released: 2026-11-19

Release channel: `supported`

## Summary

This supported public beta fixes Stonewright on a site where another active
plugin loads a newer `wordpress/mcp-adapter` (0.7 or later; Gravity Forms
bundles 0.7.1, for example). From 0.7 the adapter hands its JSON-RPC answer to
the REST layer as an object, and two plugin filters only read arrays. A large
tool surface therefore went out as one `tools/list` page over the companion's
1 MiB read cap, so the companion registered no WordPress tools, and empty
schemas reached clients as `[]`, which a client that compiles output schemas as
JSON Schema 2020-12 refuses. The release also fixes a companion reconnect that
could not add the site prompts once the AI client was connected. Plugin and
companion stay aligned on `1.0.0-beta.19.1`; Stonewright Visual stays `0.4.0`.

## Fixed

### Plugin

- Page `tools/list` when the adapter answers with an object.
  - Several plugins bundle `wordpress/mcp-adapter` behind Jetpack Autoloader,
    which loads the newest copy among the active plugins. That copy then serves
    the Stonewright routes as well.
  - From 0.7 on, the adapter hands the REST layer a `stdClass` that holds schema
    records instead of an array. The `tools/list` pagination returned early, so
    a `full` surface went out as one page of about 1.3 MB. The companion reads at
    most 1 MiB, reported `tools_list_response_truncated` and registered no
    WordPress tools.
  - The pagination now reads the answer, a batch, the result and the tools as
    arrays, plain objects or schema records, and a cursor names the same tools
    either way.
- Keep `{}` in the listed tool schemas when the adapter answers with an object.
  - The adapter rebuilds tool schemas from PHP arrays, which turns an empty
    schema `{}` into `[]`. The schema repair that restores `{}` skipped object
    answers too.
  - A client that compiles tool output schemas as JSON Schema 2020-12, where
    `items: []` is not a schema, refused to call `stonewright-task-start`,
    `stonewright-context-bootstrap` and every other tool whose output schema
    holds a permissive list, with "has an invalid outputSchema".
  - Objects stay objects, so nested values are untouched and an empty schema
    still encodes as `{}`. An answer without tools is returned as it came.

### Companion

- Connect on a `stonewright-reconnect` that brings the first site prompts after
  the AI client connected, for example when the site could not be reached as
  the companion started.
  - The MCP SDK sets up its prompt handlers on the first registered prompt and
    refuses to add the `prompts` capability once a transport is connected.
  - The reconnect answered `Cannot register capabilities after connecting to
    transport` and the status stayed `connected: false`, although the WordPress
    tools it had just registered could be called.
  - The companion now sets up the prompt handlers before any client connects.

## How to update

Both the plugin and the companion changed, and they must stay on the same
version.

1. Update the plugin: open Dashboard → Updates, click Check again, and update
   Stonewright from `1.0.0-beta.19`. Automatic updates can take up to about 24
   hours to find and install the release. The plugin installs this update only
   when the release's `SHA256SUMS.txt.sig` verifies against one of its release
   keys.
2. Point the client's companion package at the beta.19.1 asset. For an
   alias-based install, the versioned repair command does that and keeps the
   stored credential reference:

   ```bash
   npx -y --package https://github.com/cosmincraciun97/stonewright-wp-mcp/releases/download/v1.0.0-beta.19.1/stonewright-companion-1.0.0-beta.19.1.tgz stonewright connect repair <alias> --client <client> --mode plugin-only
   ```

   Fully restart the AI client, then run `connect verify` for the alias. A
   client that connects to the plugin over remote HTTP has no local companion
   and only needs the plugin update. See [Updating Stonewright](../updates.md)
   for the other install types.

Published assets are `stonewright-1.0.0-beta.19.1.zip`,
`stonewright-companion-1.0.0-beta.19.1.tgz`, `SHA256SUMS.txt` and
`SHA256SUMS.txt.sig`. To check them by hand, run this next to the downloaded
files:

```bash
sha256sum -c SHA256SUMS.txt
```

Then check the signature from a checkout of the `v1.0.0-beta.19.1` tag, with the
paths of the downloaded files:

```bash
node scripts/release-signature.mjs verify --manifest path/to/SHA256SUMS.txt --signature path/to/SHA256SUMS.txt.sig
```

## Compatibility and safety

- WordPress plugin and companion: `1.0.0-beta.19.1`.
- Plugin mode registers **397** abilities;
  Direct full exposes **105** tools.
- No ability input or output schema changed. Backup, confirmation token,
  permission, validation and audit gates are unchanged.
- WordPress: 6.7 or newer.
- PHP: 8.1 or newer.
- Node.js: 20 or newer for the companion.
- Updates preserve existing memory, user skills, audit history, the change
  history, Direct state and connected OAuth clients.
