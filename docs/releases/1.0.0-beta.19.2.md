# Stonewright 1.0.0-beta.19.2

Released: 2026-11-20

Release channel: `supported`

## Summary

This supported public beta fixes Theme Builder display conditions. Setting
display conditions on a popup, product or product-archive template removed
Elementor Pro's cached list of display rules for every template, so headers,
footers, singles, archives and popups stopped applying on the front end while
their rules still looked right in the Elementor editor. Stonewright now lets
Elementor Pro rebuild that list from every template's stored rules, the same
way its own editor does. Plugin and companion stay aligned on
`1.0.0-beta.19.2`; Stonewright Visual stays `0.4.0`.

## Fixed

- Keep Elementor Pro's cached list of display rules whole when
  `stonewright-theme-builder-set-conditions` or
  `stonewright-theme-builder-apply-template` stores a template's rules.
  - Elementor Pro decides which template applies where from a cached list of
    display rules (the `elementor_pro_theme_builder_conditions` option), not
    from the rules stored on each template. Stonewright updated that list by
    hand, and for a template type it did not map to a location (popup, product,
    product-archive and others) it deleted the whole list. Two calls at the same
    time could also drop each other's entries.
  - With Elementor Pro or ProElements active, the rules are stored and Elementor
    Pro rebuilds the list from every template's stored rules, so every template
    type is listed where Elementor Pro lists it and no other template is lost.
  - Calls take turns. A call that does not get its turn within two seconds
    stores no display rules and answers
    `stonewright_theme_builder_conditions_busy`.
  - Without Elementor Pro, only that template's entry changes: a 404 template
    and a product template are listed under `single`, a product archive under
    `archive`, a popup under `popup`, and a loop item nowhere, as Elementor Pro
    does. A template type Stonewright does not know is refused before its rules
    are stored (`stonewright_theme_builder_location_unknown`).
  - When apply-template saved an existing template but could not apply its
    display conditions, its error now points to
    `stonewright-theme-builder-set-conditions` instead of a retry, because
    running apply-template again would write the template again.

A site where Theme Builder templates stopped applying is repaired by saving any
template's conditions in the Elementor editor, or by running
`wp elementor-pro theme-builder clear-conditions`. Both rebuild the list from the
stored rules.

## How to update

Open Dashboard → Updates, click Check again, and update Stonewright from
`1.0.0-beta.19.1`. Automatic updates can take up to about 24 hours to find and
install the release. The plugin installs this update only when the release's
`SHA256SUMS.txt.sig` verifies against one of its release keys. Updating the
companion package reference to the published beta.19.2 asset is optional.

Published assets are `stonewright-1.0.0-beta.19.2.zip`,
`stonewright-companion-1.0.0-beta.19.2.tgz`, `SHA256SUMS.txt` and
`SHA256SUMS.txt.sig`. To check them by hand, run this next to the downloaded
files:

```bash
sha256sum -c SHA256SUMS.txt
```

Then check the signature from a checkout of the `v1.0.0-beta.19.2` tag, with the
paths of the downloaded files:

```bash
node scripts/release-signature.mjs verify --manifest path/to/SHA256SUMS.txt --signature path/to/SHA256SUMS.txt.sig
```
