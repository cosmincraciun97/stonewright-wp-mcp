# Stonewright 1.0.0-beta.3

This release closes the gap between a successful Elementor data write and a
verified frontend result. It also makes the same operating rule visible in
Plugin and Direct modes without overstating what pluginless remote access can
verify.

## Elementor post-write closure

- Every typed Elementor document write now uses a per-post lease, so concurrent
  writes to the same document fail safely instead of racing readback or
  rollback.
- After verified serialized readback, Stonewright invalidates Elementor's
  official document-cache key, clears only that post's CSS state, cleans the
  WordPress post cache, and emits the atomic-style clear notification.
- A successful Elementor snapshot restore performs the same invalidation so
  restored content cannot remain behind stale generated HTML.
- Single-document writes no longer fall back to a site-wide CSS clear.

## New verification ability

`stonewright/elementor-post-write-verify`:

- regenerates CSS for the target post;
- warms Elementor through its public frontend renderer;
- verifies up to 50 Elementor element IDs and 20 bounded content markers;
- returns marker hashes and render hashes instead of page HTML;
- reports `passed` or `failed` with an effect-verification receipt;
- keeps browser verification required for desktop, tablet, and mobile.

The browser recipe explicitly measures both the outer container and
`.e-con-inner`, preventing false padding failures on boxed containers.

## Safer schema and mixed-tree workflows

- Document health and mixed-tree failures return maximal V3-only safe roots for
  surgical mutation.
- Batch mutation accepts documented action aliases and gives exact remediation
  instead of encouraging guessed controls.
- The implementation contract requires live schema evidence, one reviewed
  patch list, a consolidated dry-run/apply sequence, post-write verification,
  and rendered browser proof.
- Native guidance covers device-specific visibility values, dependent
  typography activators, boxed-container measurement, and measured single-card
  carousel peeks.

## Direct mode

- Local WP-CLI Elementor writes delete target-post element/CSS cache metadata
  after verified readback, attempt Elementor's CSS flush, and report
  `browser_required`.
- Remote Direct REST cannot load Elementor's PHP renderer or cache manager. It
  now reports those verification layers as `not_checked`.
- Plugin mode remains required for live Elementor schemas, mixed V3/V4
  safeguards, typed post-scoped frontend warming, and the new closure ability.
- Direct memory, user skills, redacted audit history, and site configuration
  remain preserved across updates.

## Custom-code approval and transport clarity

- Customizer CSS joins theme-file and code-snippet writes behind the exact
  dry-run, approval URL, one-time grant, backup, readback, and audit boundary.
- Agents stop after presenting the approval handoff unless the user explicitly
  asks them to perform the approval step.
- Public docs define local stdio consistently: the AI client runs the companion
  on the user's computer. Direct mode and local WP-CLI need it; Remote
  Streamable HTTP connects directly to the WordPress plugin.

## Abilities and package versions

- Plugin mode exposes **347** abilities.
- Direct mode exposes **100** tools.
- WordPress plugin and companion: `1.0.0-beta.3`.
- `@stonewright/visual`: `0.4.0`.

## Verification

The release is published only after the pull request's complete CI matrix is
green. Required gates cover:

- 6,420 PHP tests plus PHPStan, PHPCS, security, dependencies, public API,
  provenance, documentation freshness, and token budgets;
- companion typecheck, tests, lint/contracts, token budgets, and production
  build;
- Visual tests, typecheck, and production build;
- a clean production Composer install, Jetpack manifest validation, staged
  archive inspection, public-repository hygiene, and secret scanning;
- WordPress and WooCommerce co-activation from the extracted release archive;
- responsive wp-admin browser coverage.

Release assets contain the versioned plugin ZIP, companion TGZ, Visual TGZ,
and `SHA256SUMS.txt`.

## Upgrade

For local stdio in Plugin mode, update both the WordPress plugin and companion
to `1.0.0-beta.3`, fully restart the AI client, call
`stonewright-task-start`, then verify `companion_version`,
`expected_companion_package`, and `refresh_required_tool_names`.

Remote Streamable HTTP updates only the plugin. Pluginless Direct mode updates
only the companion. Existing memory, user skills, audit history, settings, and
Direct state are preserved.

See [Updating Stonewright](../updates.md) and
[Elementor write verification](../elementor-write-verification.md).
